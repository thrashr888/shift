02 / Take the colors with you

Your terminal.
Same palette.

Every Shift theme is also a Ghostty theme, generated from the same presentation pack the TUI loads: sixteen ANSI colors, cursor and selection included.

  • Acid Garage

    Deep purple canvas, lime cursor, cyan selection.

    Download shift-acid

  • Paddock

    Paper background, racing-red cursor, dark green accents.

    Download shift-paddock

  • Blueprint

    Cobalt canvas, pale yellow cursor, sky-blue detail.

    Download shift-blueprint

  • QDOS

    Black canvas, yellow cursor, yellow-on-red selection.

    Download shift-qdos
Install in Ghostty

Save a theme into Ghostty’s themes folder, then name it in your config:

mkdir -p ~/.config/ghostty/themes
curl -fsSL -o ~/.config/ghostty/themes/shift-acid \
  https://thrashr888.github.io/shift/ghostty/shift-acid
printf 'theme = shift-acid\n' >> ~/.config/ghostty/config

Generated by scripts/ghostty_themes.py from themes/*.scm; the slots a pack does not name are complementary picks. Reload Ghostty’s configuration after saving. Inside Shift, /theme still selects the pack.

03 / More than a new coat of paint

Change the behavior.
Keep the boundary.

The interface is just the beginning. Shift explores what happens when the agent’s behavior is a live, user-owned program.

[01]

Edit while it’s running.

The Scheme image defines the agent. Edit the prompt or behavior live; a validated candidate becomes the next atomic generation.

How live updates work ↗
[02]

Keep a working version.

Invalid changes leave the current image intact. In-flight turns stay pinned to their generation. Roll back live behavior or undo UI edits.

Explore the live loop ↗
[03]

Make authority explicit.

The permanent runtime owns provider transport, tool execution, and approval policy. Live Scheme defines behavior, not new permissions.

Read the tool policy ↗
Not a restart. A new generation.

A small change you can try in the real session:

shift> /eval (define agent-system-prompt "Be concise.")
shift> /rollback

Live patches use a constrained Scheme surface, not a resource or semantic sandbox. Trusted runtime and built-in extension changes still require a restart.

04 / Start small. Make it yours.

Meet your
next instrument.

Try the terminal without a model first. Then connect a provider when you’re ready to put the live loop to work.

Explore the source ↗

Take the interface for a spin

Use macOS or Linux with Git, Make, Guile 3.0, ripgrep, and Python 3 with curses, in an interactive terminal. No API key or local model needed for this demo.

git clone https://github.com/thrashr888/shift.git
cd shift
./bin/shift --tui --session ui-demo \
  --set 'agent-model="demo"'
Ready for a real model?

The checked-in image defaults to Ollama with qwen3.8:27b-mlx. You’ll need Ollama running and a compatible, tool-capable model installed, or credentials for a supported remote provider. Model availability and hardware requirements vary.

Run ./bin/shift --tui for the terminal interface. To keep the saved demo separate, use ./bin/shift --tui --session first-run; the demo session retains its demo-model setting.
