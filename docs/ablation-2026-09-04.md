# Shift: fixes, built-ins, and ablation

2026-09-04. Baseline: `0132fcc0eb1208cf6882aa1b1bf7193e4b17d14a`.
Changes are local and uncommitted.

## Implemented fixes

All seven actionable findings in [the review](review-2026-09-04.md) now have
implementation changes and regression coverage:

| Finding | Change | Evidence |
| --- | --- | --- |
| Assertions do not fail the build | One SRFI-64 runner exits nonzero for failures and unexpected passes; every Scheme suite uses it | Injected failure exits 1 |
| Failed child reported successful | A private inherited control pipe reports outcome independently from terminal readiness; supervisor run/join spans use it | HTTP 503 produces an error result and ERROR spans |
| Truncated streaming persists partial answers | OpenAI requires finish plus DONE; Ollama requires done; length-limited streams fail before committing history or executing assembled calls | EOF, unfinished tool call, and length-stop regressions |
| Timeout makes cancellation unavailable | Busy state derives from the child lifecycle, not the lifetime of a waiting RPC | Timeout → busy → cancel; history unchanged |
| Missing extension runs baseline | Supervisor checks the structured extension-load result before starting the task | Missing/invalid artifacts make zero provider calls |
| Fork metadata disappears | Session records preserve the original fork envelope through subsequent checkpoints | Fork → turn → reset → restart retains provenance |
| Partial selector repair appears successful | Optional `agent-context-cases` reject incomplete patched candidates; the demo checks eight cases | Port-only candidate rejected; captured live repair passes 8/8 |

Candidate cases are behavior checks owned by the agent author, not an authority
boundary. The unpatched demo intentionally fails; a patched candidate must pass.
The standalone evaluator takes its expected cases from the base image, rather
than trusting case definitions changed by a candidate patch.

## Extension boundary

The shipped trusted built-ins are:

| Built-in | Implementation | Loading |
| --- | --- | --- |
| Ollama | `extensions/shift/ollama.scm` | First selected Ollama request |
| OpenAI-compatible transport | `extensions/shift/openai.scm` | First selected OpenAI request |
| Tracing | `extensions/shift/tracing.scm`, `otel.py` | Tracer creation; exporter only with a configured endpoint |
| MCP | `extensions/shift/shift_mcp.py` | `bin/shift-mcp` |

All four are enabled by default. The fixed `SHIFT_BUILTINS` allowlist can exclude
them; unset means all four, while empty means none. It is inherited by child
processes and cannot be changed through live Scheme. Disabled providers fail
explicitly, disabled tracing writes no trace file, and disabled MCP refuses to
start. There is no plugin registry, manifest graph, discovery framework, or
third-party installation machinery.

```sh
./bin/shift                                      # defaults work as before
SHIFT_BUILTINS=ollama,tracing ./bin/shift
SHIFT_BUILTINS=ollama ./bin/shift                  # local model, no tracing
SHIFT_BUILTINS= ./bin/shift --agent test/session-agent.scm "hello"
```

The shared curl implementation is `extensions/shift/http.scm`. Core keeps
completion data, fixed dispatch, a small tracing interface, tools and authority,
transactional generations, checkpoints, recovery, and the interaction loop.
Tool schemas now live beside their capabilities rather than in a provider.

Top-level `extensions/*.scm` files remain restricted live behavior artifacts.
They require an explicit first load; their patches persist in named sessions.
Trusted built-ins require process restart after edits. This distinction preserves
the existing authority boundary while making integrations optional.

## Ablation experiment

Measured actual CLI launch → one deterministic `demo` response → process exit.
This includes shutdown. It does **not** measure model latency or time to first
token. Each configuration had one discarded warmup and seven measured samples,
interleaved on the same Mac. No remote model requests or Phoenix export were in
the timing path. Other local machine activity was not controlled.

| Configuration | Median | Observed range |
| --- | ---: | ---: |
| Original baseline, watcher on | 583.236 ms | 522.528–608.550 ms |
| New default built-ins, watcher on | 583.234 ms | 557.540–596.166 ms |
| New redirected-input default | 322.205 ms | 288.858–346.125 ms |
| Providers disabled, watcher on | 569.296 ms | 536.375–604.089 ms |
| Tracing disabled, watcher on | 547.906 ms | 536.162–566.244 ms |
| All built-ins disabled, watcher on | 545.367 ms | 536.333–641.379 ms |
| Default built-ins, watcher off | 328.484 ms | 308.047–352.220 ms |
| All built-ins and watcher off | 289.090 ms | 255.169–323.995 ms |

The extension move does not establish a default-mode speed improvement. Removing
providers has little effect because they already remain unloaded until needed.
Disabling tracing has a modest observed cost reduction; the ranges overlap.
The large effect is removing the watcher's polling/shutdown wait for short,
noninteractive work. Redirected input now defaults to watch off. Terminal and
MCP sessions retain automatic watching, and `--watch` opts scripts back in.

Physical omission also passed: a temporary project containing core, launcher,
and demo agent, with **no built-in source files**, completed the model-free turn.
Inspection with module autoload disabled showed neither provider loaded during
normal boot; minimal mode loaded neither provider nor tracing. These checks
establish optionality independently of folder names and timing noise.

Reproduce from this checkout:

```sh
python3 scripts/ablate.py --baseline .shift/implementation-20260904
```

The baseline directory is a clean `git archive` of the reviewed commit. For a
fresh checkout, extract that commit into a temporary directory and supply its
path. Raw samples are in [ablation-results.json](../.shift/ablation-results.json).

## What was actually removed

- Prompt-suffix parsing as the MCP lifecycle signal, plus duplicate stored busy
  state. Real terminal output remains visible; a separate pipe carries results.
- Duplicate streaming/non-streaming curl setup, limits, and cleanup.
- A second trace-tail implementation used only by tests; tests inspect the
  writer and existing search API instead.
- Duplicate read-tool schema construction and repetitive Makefile suite/compiler
  commands.
- An unnecessary watcher in the default redirected-input path.

The pure prompt/history split, compaction boundary, write-ahead recovery,
generation validation, and rollback stay. They encode tested behavior and are
not replaced with a new generic framework.

Line counts include comments and blanks, so they describe code placement rather
than complexity or performance:

| Runtime source | Lines |
| --- | ---: |
| Baseline Scheme core | 4,053 |
| Current Scheme core | 3,407 |
| Baseline Scheme plus runtime Python scripts | 5,447 |
| Current trusted built-ins | 2,216 |
| Current core plus trusted built-ins | 5,623 |

The Scheme core is about 16% smaller. Total runtime source is about 3% larger
after the correctness fixes and explicit optional boundaries. Moving code is
not deletion; this is not a claim of a net line-count reduction. Tests and
experiment/evaluation drivers are excluded from these totals.

## Tests and live tracing

- `make check`: 128 Scheme assertions, 8 existing integration tests, 6 new
  regression tests, and all 17 core/built-in Scheme modules compiled.
- Ruff lint and formatting passed for the Python implementation and test tools.
- The captured live repair passed **8/8** independent context queries; the stale
  baseline passed **3/8**. Regression coverage also verifies rollback.
- Reused the healthy `lisp-agent-harness-phoenix-1` collector on port 6006.
  `make phoenix` now reuses a healthy local collector instead of colliding with
  it. The sandboxed exporter run used `UV_CACHE_DIR=/tmp/shift-uv-cache`.
- Phoenix returned **11/11** local spans for session `context-proof-v2`, with
  matching names, statuses, and generations. Turns were generation 1 → 1 → 2;
  the answer changed **8080 → 9443**. Turn durations were 4.343 s, 32.233 s,
  and 11.766 s. This is one live run, not a model-performance comparison.
- OpenAI behavior was verified with deterministic local SSE fixtures. No paid
  OpenAI request was made.

The first stricter live run correctly rejected case-sensitive candidates but
the model repeatedly misread the error. The diagnostic was made readable and
the demo prompt now explicitly requires lowercasing; the subsequent repair
passed the full contract.

One model-output limitation remains: local Qwen sometimes emits duplicate text,
a stray `</think>` marker, or stale generation prose. The accepted retry's
structured evidence says generation 2 even though its prose repeats generation
1. Output was preserved in the trace; no heuristic text-rewriting layer was
added to disguise it. This remains a provider/model-quality follow-up.
