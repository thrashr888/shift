## Findings and potential fixes

### 1. P1 — Scheme assertion failures do not fail the build

**Evidence:** An isolated copy of `test/provider.scm` with an added
`(test-assert "review injected failure" #f)` reported 13 passes and one unexpected
failure, then exited **0**. The Scheme test files end with `test-end` and do not
translate runner failure counts into a nonzero process status. `Makefile` relies
on that status, so assertion regressions can leave `make check` green.

**Fix:** Add a shared suite-exit helper that checks failures/unexpected passes
and exits nonzero. Verify it with an intentional failure in an isolated suite.
Keep the passing path unchanged.

Locations: `Makefile:34`, `test/provider.scm:117`, and the other Scheme suite
endings. Evidence: `test-exit-probe.txt`.

### 2. P1 — A failed child turn can be recorded as successful

**Evidence:** A provider returning HTTP 503 produced `openai.chat=ERROR` and
`agent.turn=ERROR`, but the supervisor wrote `subagent.run=OK`. The returned
result had `state: ready`, no failed assertion, and the failure only in prose.
The supervisor infers success from the terminal returning to `shift>`.

**Fix:** Give the bridge a structured command/turn result containing completion,
failure, cancellation, and trace identity. Derive run/join status from that
result; keep terminal readiness separate. Add a provider-error regression with
no optional tool assertion, since that is a valid API call.

Locations: `scripts/session_bridge.py:965`, `src/live-agent/main.scm:1347`.
Evidence: `probe-results.json`, key `provider_error_child`.

### 3. P1 — Incomplete SSE is accepted and persisted as a complete answer

**Evidence:** A local OpenAI-compatible endpoint emitted one content event,
then closed cleanly without a finishing choice or `[DONE]`. Shift persisted
`partial answer` in conversation history and marked both LLM and turn spans
`OK`. Curl's successful exit only proves the HTTP transfer ended.

**Fix:** Track provider completion state and reject streams without the required
completion evidence before committing history or executing assembled calls.
Handle finish reasons explicitly. Test premature EOF, incomplete tool arguments,
and valid streams; inspect native Ollama termination handling as well.

Location: `src/live-agent/provider.scm:557` through completion assembly.
Evidence: `probe-results.json`, key `truncated_stream`.

### 4. P2 — Cancellation stops working after an RPC timeout

**Evidence:** `send(..., timeout_seconds=1)` returned `timeout` while the model
request remained in flight. Immediately calling `cancel()` raised
`the live session is idle; there is no turn to cancel`.
The send call clears `_busy` in `finally`, even though the child is still working.

**Fix:** Track the child operation's lifecycle independently of how long an RPC
caller waits. Preserve cancellation after timeout and during initial-prompt
startup. Test timeout → read/status → cancel → unchanged durable history.

Location: `scripts/session_bridge.py:594`–`627`.
Evidence: `probe-results.json`, key `cancel_after_timeout`.

### 5. P2 — Missing candidate extensions silently run the baseline

**Evidence:** A supervised run requesting `extension: does-not-exist` continued
to the model turn and returned a successful run with the parent's unchanged
generation/fingerprint. The load failure returns to the prompt, which passes
the supervisor's check. This can invalidate baseline/candidate comparisons.

**Fix:** Require explicit extension-load success and inspect the activated
patch/generation before starting the task. Return the load error and do not
call the provider. Cover missing and syntactically invalid artifacts.

Location: `scripts/session_bridge.py:927`–`930`.
Evidence: `probe-results.json`, key `missing_extension`.

### 6. P2 — Fork provenance disappears after the child is checkpointed

**Evidence:** `fork-session!` writes a `fork` object with parent identity and
generation. The child's resulting `session.json` no longer contains it.
`save-session!` builds a new object without retaining fork metadata.

**Fix:** Store immutable fork provenance in the session record and preserve it
across boot checkpoints, turns, reset, compaction, and resume. Test the complete
fork → start → turn → restart lifecycle. Supervisor traces retain some links,
but they do not replace the checkpoint's original fork record.

Locations: `src/live-agent/session.scm:293`, `src/live-agent/session.scm:306`.
Evidence: `probe-results.json`, `missing_extension.fork_metadata_preserved`.

### 7. P2 — The demo passes its retry while missing the broader repair contract

**Evidence:** The live model generated a selector that handles `port`, but not
`deploy`, despite the demo prompt explicitly requesting both. Validation accepts
it because it checks the return type and a combined query containing `port`.
The actual patch returned no context for `How do I deploy Atlas?`.

**Fix:** Add task-level selector evaluation with independent port/deploy queries,
case variation, and unrelated queries. Report baseline and candidate outcomes
before promoting a repair. Keep basic generation validation distinct from this
behavioral quality gate. Expand beyond these four cases before claiming general
repair quality.

Locations: `demo/context-selection/agent.scm:27`,
`src/live-agent/generation.scm:243`.
Evidence: `selector-results.txt` and the actual demo journal.

## Live demo outcome

Command, run from the repository root:

```sh
./bin/shift --agent demo/context-selection/agent.scm \
  --state-dir .shift/review-20260904/context-demo \
  < demo/context-selection/session.txt
```

| Step | Observed result | Agent-turn duration |
| --- | --- | --- |
| Ask production port | Generation 1, legacy 2024 source, answer `8080` | 9.798 s |
| Ask to fix the picker | `live_eval` activates generation 2; current turn stays pinned to 1 | 8.641 s |
| Retry production port | Generation 2, current 2026 source, answer `9443` | 3.062 s |

Fingerprints: `98ae6ce56dd6c405` → `bceec3f22376708a`.
Total recorded agent-turn time: 21.501 seconds; one run, not a benchmark.

The first answer was verbose and speculated about an unsupported port `8443`
before settling on the selected source's `8080`. Thinking was disabled. This is
a demo quality issue to evaluate explicitly rather than assuming a prompt alone
enforces brevity or grounding.

Evaluation of the actual generated patch:

| Query | Baseline | Repaired selector | Rollback |
| --- | --- | --- | --- |
| Which port does Atlas use in production? | Legacy | Current | Legacy |
| How do I deploy Atlas? | Legacy | **No context** | Legacy |
| PORT configuration | Legacy | Current | Legacy |
| Write a cookie recipe | No context | No context | No context |

The repair satisfies 3/4 of these small contract cases; baseline satisfies 1/4.
Rollback restored all four baseline selections. This shows an improvement and a
remaining defect, not a general success rate.
